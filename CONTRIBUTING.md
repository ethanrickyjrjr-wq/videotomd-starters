# Contribute a workflow

The most useful first contribution is a run report or a correction to a step you tried.

For a new workflow, copy TEMPLATE.md to a descriptive `.md` filename and open a pull request. Keep it focused on one task with a visible result. Include prerequisites, original sources, limitations and a completion check that can fail. Supply a small example people can run without private data or paid services where possible.

Describe exactly what you tested: environment, input, observed output and unfinished checks. Label an untested instruction as untested. Do not replace observations with a model's assurance.

Submit your own writing or material you have permission to contribute. Link and credit original creators when adapting an idea. Do not submit copied transcripts, private notes, credentials or instructions that silently transmit a user's data. All contributions use the repository's MIT license.

A maintainer reviews scope, sources, executable commands and the completion check before merging. Submitting a file does not automatically publish it on videotomd.com. Site publication has a separate review process.
